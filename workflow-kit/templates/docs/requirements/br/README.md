# Business requirements tree

Layer 1 (top). Solution-neutral: what the business needs and how success is measured. One folder per scope, one file per chapter (product, finance, organization, market). Numbers are fixed once assigned; a removed number is retired and never reused. A chapter file is created only when it has requirements (template `../templates/br-chapter.md`).
IDs follow the location: `BR-02-02-001` is requirement 001 in `br/02-common/02-finance.md`. KPIs mirror this tree in `docs/requirements/kpi/`.
Rules and check: skill `requirements-authoring` (section "BR tree").

| Number | Path | ID prefix | Content |
|---|---|---|---|
| 01 | `01-general.md` | — | Context and planning assumptions (no requirements) |
| 02 | `02-common/_index.md` | — | Requirements for the whole business |
